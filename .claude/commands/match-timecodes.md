# Match Timecodes — Pass 2: Верификация агентами

Ты оркестрируешь проход 2 пайплайна сопоставления таймкодов. Пользователь даёт путь к проекту (например, `projects/tulips`). Базовая директория — `C:/Users/Alex/Videos/factory`.

## 1. Проверь пререквизиты

- Файл `{project_dir}/script/candidates.json` должен существовать
- В `{project_dir}/transcripts/` должен быть хотя бы один `*.words_compact.txt`

Если чего-то нет — сообщи пользователю и останови выполнение. Подскажи:
- Если нет `candidates.json`: запустить `python _scripts/match_timecodes.py search {project_dir}`
- Если нет `*.words_compact.txt`: запустить `python _scripts/match_timecodes.py compact {project_dir}`

## 2. Прочитай candidates.json и выведи статистику

Файл `{project_dir}/script/candidates.json` содержит массив `rows`. Каждая строка имеет поля:

- `status`: `single` | `multiple` | `multi_part` | `partial` | `not_found`
- `parts`: список частей цитаты. Для одиночной цитаты — длина 1. Для составной (склеенной из нескольких фрагментов) — >1. Каждая часть: `{"text": str, "candidates": [{"file": str, "start": float, "end": float}, ...]}`
- `unmatched`: список предложений, которые не удалось найти нигде (для `partial`).
- `mode`: `"whole"` (вся фраза нашлась целиком одним куском) или `"split"` (искалось по предложениям).

Выведи пользователю сводку:
```
📊 Статистика candidates.json:
  single:     N строк (однозначное совпадение)
  multiple:   N строк (один фрагмент, несколько кандидатов — нужен выбор)
  multi_part: N строк (составная цитата из нескольких кусков — подтвердить порядок)
  partial:    N строк (часть найдена, часть в unmatched — нужен поиск)
  not_found:  N строк (не найдено ничего — агент может попытаться)
  Итого:      N строк
```

## 3. Подготовь данные для агентов

### Загрузи транскрипты
Прочитай все файлы `{project_dir}/transcripts/*.words_compact.txt`. Формат строки:
```
INDEX    START    END WORD
```
Фиксированная ширина колонок. INDEX — номер слова, START/END — секунды, WORD — само слово.

Построй вспомогательный индекс `{filename → list[(index, start, end, word)]}` — понадобится для вырезания контекста по таймкоду.

### Раздели строки на ~4 чанка
Раздели массив `rows` на примерно 4 равные части. Если строк мало (< 8), используй меньше агентов.

### Для каждой строки подготовь контекст

Для каждого candidate (`{"file", "start", "end"}`) вырезай из соответствующего `words_compact.txt` фрагмент — все слова, у которых START попадает в интервал `[candidate.start - 10s, candidate.end + 10s]`. Этого достаточно агенту чтобы увидеть границы и фальстарты.

По статусу:
- **`single`** — один candidate в `parts[0]`. Контекст ±10 сек вокруг него (проверка границ).
- **`multiple`** — несколько candidates в `parts[0].candidates`. Контекст ±10 сек вокруг каждого — сравнить полноту.
- **`multi_part`** — несколько parts, у каждой 1+ candidates. Контекст ±10 сек вокруг candidate каждой части.
- **`partial`** — parts частично найдены, часть фраз в `unmatched`. Для найденных частей — контекст ±10 сек. Для unmatched — передай весь `words_compact.txt` файлов релевантного спикера (агент будет искать).
- **`not_found`** — передай весь `words_compact.txt` файлов релевантного спикера. Агент ищет по смыслу.

## 4. Запусти параллельных агентов

Запусти ~4 Explore-агентов параллельно. Каждому передай промпт:

---

Ты верифицируешь таймкоды для сценария русскоязычного YouTube-видео.

Для каждой строки ниже проверь или исправь совпадение таймкодов. Возможны составные цитаты — склеенные из нескольких кусков одного или разных файлов.

### Правила выбора

- **`single`**: один part, один candidate. Проверь что границы не режут слова, и текст реально совпадает по смыслу.
- **`multiple`**: один part, несколько candidates. Выбери ПОСЛЕДНИЙ ПОЛНЫЙ кандидат (фальстарты — неполные начала фразы, их пропускай).
- **`multi_part`**: несколько parts. Для каждой части — либо подтверди единственный candidate, либо выбери из списка. Убедись что **времена возрастают** и порядок частей соответствует тексту сценария.
- **`partial`**: часть предложений в `parts`, часть в `unmatched`. Для найденных — подтверди или уточни. Для unmatched — попробуй найти в транскрипте (текст мог быть перефразирован). Если нашёл — добавь как новую часть. Если не нашёл — пометь `confidence: "missing"` и объясни.
- **`not_found`**: ищи фразу целиком или по предложениям в `words_compact.txt` по смыслу. Возможно перефразировка, пропуски слов.

### Фальстарты и оговорки

- Слава иногда начинал фразу, останавливался, начинал заново. Выбирай ПОСЛЕДНЮЮ ПОЛНУЮ версию.
- Если текст кандидата обрывается на полуслове — это фальстарт, пропускай.
- Для реплик героя: убедись что выбор файла логичен (совпадает спикер).

### Формат ответа

Верни JSON-массив (ничего лишнего):
```json
[
  {
    "row_idx": 2,
    "chosen_parts": [
      {"file": "file1.mp4", "start": 79.88, "end": 87.40, "text": "фраза одна"},
      {"file": "file2.mp4", "start": 120.5, "end": 123.8, "text": "фраза два"}
    ],
    "confidence": "high",
    "note": ""
  }
]
```

- `chosen_parts`: массив. Для single/multiple — длина 1. Для multi_part/partial — по одному выбору на каждую реальную часть (в порядке следования в сценарии).
- `confidence`: `"high"` — уверен, `"low"` — угадывал (совпало только часть слов), `"missing"` — не нашёл.
- `note`: пояснение если что-то необычное (пропущена часть, файл не тот, фальстарт).
- Если у строки все части `missing` — верни `chosen_parts: []` с `confidence: "missing"`.

## 6. Сохрани verified.json

Сформируй файл `{project_dir}/script/verified.json`:
```json
{
  "rows": [
    {
      "row_idx": 2,
      "speaker": "slava",
      "col": 1,
      "text": "оригинальный текст реплики...",
      "chosen_parts": [
        {"file": "...", "start": 0.0, "end": 0.0, "text": "..."}
      ],
      "confidence": "high",
      "note": ""
    }
  ]
}
```

Отсортируй `rows` по `row_idx`. Скрипт `match_timecodes.py snap` принимает `chosen_parts[]` — для одиночной цитаты это будет массив длины 1, для составной — >1.

Если агент вернул старый формат с `chosen` (single dict) — нормализуй в `chosen_parts: [chosen]`.

## 6.5. Validate verified.json и fix-loop

Запусти автоматический цикл проверки и точечной починки. Лимит — 3 итерации; после — эскалация.

**Инициализация:**

```python
iter = 0
prev_problem_set = None
```

**На каждой итерации (`iter` 1..3):**

```bash
python _scripts/match_timecodes.py validate {project_dir}
```

Команда пишет `{project_dir}/script/validation_report.json`:
```json
{
  "overlaps": [
    {"row_idx": 51, "file": "X.mov", "part_a": 0, "part_b": 1,
     "intersection_s": 0.10}
  ],
  "within_word": [
    {"row_idx": 8, "part_idx": 0, "edge": "end",
     "word": "курьерах", "word_start": 187.55, "word_end": 190.14,
     "part_value": 189.05}
  ],
  "thresholds": {"word_tol_ms": 50, "min_overlap_ms": 50}
}
```

Прочитай `validation_report.json`, собери:

```python
problem_set = set(o["row_idx"] for o in overlaps) \
            | set(w["row_idx"] for w in within_word)
```

**Стоп-условия:**

1. `problem_set` пустой — break, перейти к шагу 7. Validate чисто.
2. `iter == 3` — break, эскалировать (см. ниже).
3. `prev_problem_set is not None and len(problem_set) >= len(prev_problem_set)` — множество не уменьшилось → break, эскалировать (защита от тупика).

Если ни одно стоп-условие не сработало:

```
[Iter {iter}]: validate → {len(overlaps)} оверлапов + {len(within_word)} within-word → {len(problem_set)} проблемных строк
```

— и переходим к шагу 6.6.

**Эскалация** (печатается в stdout, скилл идёт к шагу 7):

```
⚠ После {iter} итераций фикса осталось {len(problem_set)} проблем:
  row 51: overlap parts 0+1 в X.mov (0.10s)
  row 8:  within-word 'курьерах' (end 189.05s в [187.55, 190.14])
  ...

Следующий шаг — переверифицировать вручную или принять как есть.
script.csv не будет сгенерирован snap'ом, пока есть оверлапы.
```

## 6.6. Подготовь fix-payload для проблемных строк

**Row picker.** Из `verified.json` выбери только записи с `row_idx in problem_set`.

**Context builder.** Для каждой проблемной строки собери `payload`:

```python
{
  "row_idx": <int>,
  "text": <оригинальный текст из verified.json>,
  "current_chosen_parts": <текущий chosen_parts из verified.json>,
  "issues": [
    # из overlaps этой строки:
    {"type": "overlap", "parts": [a, b], "file": "...",
     "intersection_s": 0.10},
    # из within_word этой строки:
    {"type": "within_word", "part_idx": 0, "edge": "end",
     "word": "курьерах", "word_start": 187.55, "word_end": 190.14,
     "part_value": 189.05}
  ],
  "original_candidates": <запись этой row_idx из candidates.json>,
  "words_context": <фрагмент words_compact.txt ±10s вокруг текущих
                    границ chosen_parts, по правилу из шага 4>
}
```

`original_candidates` — это вся запись из `candidates.json` для этой строки (включая `parts[]`, `unmatched`, `mode`, `status`). Агенту это нужно, чтобы видеть альтернативы.

`words_context` строится так же, как в шаге 4: из соответствующего `words_compact.txt` берутся все строки, у которых `START` попадает в `[part.start - 10, part.end + 10]` для каждого парта в `current_chosen_parts`.

Сохрани полный список `fix_payload[]` в памяти — он передаётся агенту в шаге 6.7.

## 6.7. Запусти fix-агентов

**Чанкинг.** Если `len(fix_payload) <= 30` — 1 агент. Иначе — раздели на 2 примерно равные части и запусти 2 параллельных Explore-агента.

**Промпт fix-агенту:**

---

Ты исправляешь конкретные проблемные строки в `verified.json` для сценария русскоязычного YouTube-видео. Проблемы детектированы детерминированным валидатором (`match_timecodes.py validate`) — они **гарантированно** сломают таймлайн в DaVinci, если их не починить:

- **`overlap`** — два парта одной строки имеют пересекающиеся диапазоны в одном файле. На таймлайне это даст повтор аудио.
- **`within_word`** — `start` или `end` парта попадает внутрь слова. На таймлайне будет обрыв слова посередине.

### Что делать

Для каждой строки выбери **одно** из:

1. **Другой кандидат.** Посмотри `original_candidates` — если status был `multiple` или `multi_part`, выбери альтернативу, у которой нет этой проблемы.
2. **Сдвиг границы.** Если кандидат в `original_candidates` единственный или альтернативы тоже сломаны — сдвинь `start`/`end` к ближайшей word-boundary в `words_context`. Для within-word: к `word.end` проблемного слова или к `word.start` следующего. Для overlap: укороти один из перекрывающихся партов до конца word'а перед пересечением.
3. **Поиск заново.** Если ни (1), ни (2) не дают чистого результата — найди в `words_context` альтернативный кусок с тем же смыслом (например, повторение фразы дальше по записи).

Если ничего не помогает — верни `confidence: "low"` с пояснением в `note`, эту строку validator во второй итерации найдёт снова, человек разберётся.

### Формат ответа

JSON-массив (ничего лишнего, можно обернуть в ```json ... ```):

```json
[
  {
    "row_idx": 51,
    "chosen_parts": [
      {"file": "X.mov", "start": 100.0, "end": 108.5, "text": "..."},
      {"file": "X.mov", "start": 110.0, "end": 115.0, "text": "..."}
    ],
    "confidence": "high",
    "note": "выбрал второго кандидата из original_candidates вместо первого"
  }
]
```

- `chosen_parts` — обновлённый массив (как в первичной верификации).
- `confidence`: `"high"` / `"low"` / `"missing"`.
- `note`: что именно сделал (выбрал альтернативу, сдвинул границу, нашёл заново). Краткая фраза.

## 6.8. Смержи результаты в verified.json

**Парсинг ответов агентов.** Из каждого агента — JSON-массив. Если вернулось обёрнуто в ```json ... ``` — сними обёртку и спарси. Объедини ответы всех fix-агентов в один словарь `fixed: dict[row_idx, result]`.

**Обработка одной строки:**

- Если `row_idx` есть в `fixed`: возьми `chosen_parts`, `confidence`, `note` из ответа.
- Если `row_idx` нет в ответе агента (агент не вернул эту строку) — оставь её как была. Логируй в stdout: `⚠ row {row_idx}: агент не вернул фикс`.
- Если у агента невалидный JSON — пропусти эту строку, оставь как была, логируй: `⚠ row {row_idx}: невалидный JSON от fix-агента`.

**Запись.** Прочитай `verified.json` целиком, обнови **только** строки с `row_idx in fixed`:

```python
for row in verified["rows"]:
    if row["row_idx"] in fixed:
        f = fixed[row["row_idx"]]
        row["chosen_parts"] = f["chosen_parts"]
        row["confidence"] = f.get("confidence", "low")
        row["note"] = f.get("note", "")
```

`speaker`, `col`, `text` — не трогай. Сохрани verified.json.

**Контрольная точка в stdout:**

```
[Iter {iter}]: fix-агент вернул {len(fixed)}/{len(fix_payload)} строк
```

**Подготовка к следующей итерации:**

```python
prev_problem_set = problem_set
iter += 1
```

И возврат к шагу 6.5 (новый прогон validate).

## Обработка ошибок

- Если агент не вернул валидный JSON — попробуй распарсить вручную (может быть обёрнут в ```json ... ```)
- Если строка отсутствует в результатах агентов — отметь её `confidence: "missing"`, `chosen_parts: []`, `note: "агент не вернул результат"`
- Если у агента `chosen_parts: []` и статус был `not_found` — сохрани как есть, snap такие строки пропустит.
