# Написание YouTube-сценария

Формат: автор (Слава) исследует бизнес-тему, герой даёт инсайды из интервью.

## Предусловие

Проверить, что `<project_dir>/script/analysis.md` существует.
Если нет — сообщить пользователю: «Сначала запустите `/yt-analyze <project_dir>`».
Если `<project_dir>` не передан — спросить у пользователя.

## Шаг 0: Загрузка контекста

Прочитать:
1. `<project_dir>/script/analysis.md` — анализ (цифры, структура, приёмы, цитаты)
2. `<project_dir>/raw/article.md` — статья
3. `<project_dir>/transcripts/*.transcript.txt` — расшифровки интервью
4. `.claude/commands/yt-examples.md` — примеры формата (цитаты, подводки, мостики)

## Шаг 1: Архитектура сценария

⛔ НЕ ПИСАТЬ ТЕКСТ СЦЕНАРИЯ, пока архитектура не готова.

На основе `analysis.md` построить посегментную карту. Для каждого сегмента:

```
Сегмент N: [Название] (~XX сек)
  Приём: [какой драматургический приём применяется]
  Автор (Слава): [тезис — о чём говорит, 1-2 предложения]
  Герой: [какая цитата из analysis.md, или «нет цитаты»]
  Open loops: [какие вопросы открываем/закрываем]
  Числа: [какие цифры, с каким контрастом/сравнением]
  Визуал: [B-ROLL / ГРАФИКА / говорящая голова]
  Музыка: [настроение, если меняется]
```

Ориентир: 6-10 сегментов. Каждый — конкретный план, не абстрактное описание.

## Шаг 2: Написание сценария

По архитектуре написать полный текст сценария. Строго соблюдать правила ниже.

### Правила цитат
- Источник цитат — ТОЛЬКО расшифровки интервью (НЕ статья)
- Copy-paste БЕЗ редактирования (сохранять ошибки, повторы, междометия героя)
- Приоритет самодостаточным цитатам (герой сам даёт контекст)
- Несамодостаточные цитаты — только с ПОЛНОЙ подводкой автора:
  - Все термины объяснены ДО цитаты
  - Контекст дан
  - Вопрос задан или подводка сделана
- ЗАПРЕЩЕНО: несамодостаточная цитата без подводки

### Правила распределения контента
- **70% герой** (цитатами из расшифровок), **30% автор** (вводные, переходы, расчёты)
- Если информация ЕСТЬ в расшифровке → герой говорит сам (цитатой)
- Автор НЕ пересказывает то, что герой сказал в интервью
- Автор делает ТОЛЬКО: краткие вводные (1-2 предложения), переходы, вопросы в пространство, контент которого НЕТ в интервью

### Правила доступности
- **Смысловые мостики** перед каждым переходом между темами:
  1. Итог предыдущей части
  2. Почему переходим к следующей
  3. Представление новой темы
- **Термины** — каждый объяснён ДО первого использования
- **Введение информации** — новые понятия, названия, места: общий контекст → примеры → почему этот → определение
- **Вопросы автора** — в пространство, не к герою лично
- **Нет диалоговых паттернов** — запрещено: «герой ответил», «давайте спросим у героя», «я спросил героя», прямое обращение к герою

### Правила подачи чисел
- Числа как произносятся вслух: «два миллиона двести тысяч», не «2,2 млн»
- Каждое число — в контексте сравнения (с чем-то знакомым, с ожиданием, с другой цифрой)
- Не больше 3-4 чисел подряд без паузы
- После блока расчётов: «Итого: [вывод одним предложением]»
- Контраст двух чисел сильнее одного числа

### Правила языка
- Короткие предложения, активный залог
- Без канцеляризмов и абстракций
- Конкретика: вместо «значительная часть» → точное число

### Разметка для монтажа
В текст сценария встраивать разметку:
- `[B-ROLL: описание]` — дополнительные кадры
- `[ГРАФИКА: описание]` — таблицы, схемы, анимации
- `[МУЗЫКА: настроение]` — смена музыки при смене сегмента/настроения
- `[ПАУЗА]` — пауза 1-2 секунды перед ключевым числом или выводом
- `[INTERRUPT: тип]` — pattern interrupt (смена темпа, формата, юмор)

Визуал менять каждые 15-30 секунд. При 3+ шагах расчёта — обязательна графика.

### Hook (первые 30 секунд)
Строго по архитектуре из Шага 1. Должен содержать:
- Конкретное обещание (что зритель узнает)
- Stakes (почему это важно/удивительно)
- НЕ начинать с предыстории, приветствия, «сегодня поговорим о»

### Закрытие
- На пике: сильная цитата героя или неожиданный вывод
- Закрыть macro-loop из hook (вернуться к главному вопросу)
- Максимум 2-3 предложения после кульминации
- НЕ анонсировать конец: без «подведём итоги», «на этом всё»
- CTA (если есть) — после сильного момента, один конкретный, обоснованный

## Шаг 3: Сохранение

Сохранить в `<project_dir>/script/script_draft.csv`.

Формат: 4 колонки — `Слава,Таймкоды,Герой,Таймкоды`.
- Колонка 1 (Слава): текст автора + разметка для монтажа
- Колонка 2 (Таймкоды): пустая (заполняется пайплайном позже)
- Колонка 3 (Герой): дословные цитаты героя
- Колонка 4 (Таймкоды): пустая
- Строки-заголовки разделов — в первой колонке

## Шаг 4: Ревью

Запустить агента-ревьюера с помощью Agent tool. Промпт для агента:

---

Ты — ревьюер YouTube-сценария. Твоя задача — проверить сценарий по чеклисту и исправить найденные проблемы.

**Прочитай эти файлы:**
1. `<project_dir>/script/script_draft.csv` — сценарий для проверки
2. `<project_dir>/script/analysis.md` — анализ (цифры, структура, приёмы)
3. `.claude/commands/yt-review-checklist.md` — чеклист проверки

**Для проверки цитат** — читай расшифровки из `<project_dir>/transcripts/` (только конкретные файлы, указанные в analysis.md).

**Действуй по инструкции из чеклиста:**
1. Пройди все 4 блока (фактчекинг, драматургия, доступность, формат)
2. Для каждой проблемы: опиши, укажи строку, исправь
3. Если проблемы есть — обнови CSV и проверь заново
4. Максимум 3 прогона
5. Если после 3-го прогона остались проблемы — сохрани в `<project_dir>/script/review_notes.md`
6. Если после первого прогона всё чисто — готово

---

Подставить реальный `<project_dir>` в промпт агента.

## Готово

После завершения ревью сообщить пользователю:
- Сценарий сохранён в `script/script_draft.csv`
- Сколько прогонов ревью было (1, 2 или 3)
- Какие проблемы были найдены и исправлены (кратко)
- Есть ли нерешённые проблемы (если да — см. `script/review_notes.md`)
- Для генерации заголовков и превью → `/yt-titles <project_dir>` (будет реализован позже)
