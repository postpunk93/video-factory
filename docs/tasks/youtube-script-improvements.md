# Улучшение скилла youtube-script — анализ и план

## Диагноз: почему скилл ломается

### 1. Когнитивная перегрузка — ~940 строк правил

Скилл содержит 7 шагов, десятки подправил, примеры, чек-лист на 40+ пунктов. Чем больше правил, тем хуже соблюдается каждое отдельное. LLM не "запоминает" все правила — она удерживает в фокусе ограниченный контекст, и второстепенные правила (пассивный залог, отглагольные существительные) вытесняют критические (автор не рассказывает историю героя).

Правила стиля занимают столько же места, сколько правила структуры. Модель воспринимает их как равно важные.

### 2. Главная ошибка: нет протокола для "цитаты не нашлось"

Это корень проблемы "автор говорит слова героя". Сценарий такой:

1. В статье есть факт: "невыход составил 17%"
2. Модель ищет цитату в расшифровке — не находит точного совпадения
3. Факт важный, пропускать нельзя
4. Модель вставляет его в слова автора → **нарушено правило "автор не рассказывает историю героя"**

Скилл говорит: "Если контент есть только в статье → Автор излагает это как рыночный факт" (строка 49). Но грань между "рыночный факт" и "история героя" размыта. "Невыход 17%" — это рыночный факт или конкретика героя? Модель не знает, и по умолчанию включает.

### 3. "Ctrl+C → Ctrl+V" — невыполнимая инструкция

Скилл требует копировать цитаты "ТОЧЬ-В-ТОЧЬ" (строки 163-177). LLM не копирует — она генерирует токен за токеном. Даже с инструкцией "ничего не менять" модель будет:
- Исправлять очевидные опечатки
- Менять пунктуацию
- Пропускать или добавлять слова

Инструкция "Ctrl+F" и "Ctrl+C" написана для человека, не для модели.

### 4. "Стоп-тест" перед каждым предложением — тоже нереалистичен

Шаг 3 требует перед КАЖДЫМ предложением автора делать поиск по расшифровке (строки 273-281). LLM генерирует текст потоково. Она не останавливается посреди генерации, чтобы "Ctrl+F по ключевым словам". Это инструкция для человеческого workflow, а не для модели.

### 5. Баланс 40/60 по строкам — легко обойти формально

Модель может набить длинные цитаты героя и формально пройти проверку, при этом автор всё равно пересказывает историю героя в своих 40%.

### 6. Шаг 5 (пропущенные цитаты) идёт слишком поздно

К шагу 5 таблица уже собрана. Вставлять "потерянные сокровища" post-hoc — это ломать уже выстроенную структуру. Модель делает это поверхностно или пропускает.

### 7. Нет разделения: что можно выдумать, а что нельзя

Скилл не говорит явно: "Если факта нет ни в статье, ни в расшифровке — НЕ ВКЛЮЧАЙ его." Проблема "выдумывает факты" из созвона — именно отсюда. Модель видит тему и дополняет её правдоподобными, но несуществующими деталями.

## Что можно улучшить

### А. Структурные изменения

1. **Разделить скилл на два**: процесс (7 шагов) и стайлгайд (тон, стиль, язык). Стайлгайд подключать как отдельный референс, а не вмешивать в пошаговый алгоритм. Это уменьшит когнитивную нагрузку.

2. **Добавить явный протокол "цитата не найдена":**
   - Факт из статьи, цитаты нет → пометить `[НЕТ ЦИТАТЫ — ПРОВЕРИТЬ]` и предложить, должен ли это сказать автор как рыночный факт, или лучше убрать
   - Факт не из статьи и не из расшифровки → **запрещено включать**

3. **Перенести поиск "потерянных сокровищ" (шаг 5) в шаг 2.** Сначала собрать ВСЕ яркие цитаты из расшифровки, потом распределять по разделам. Сейчас порядок: разделы → цитаты по разделам → таблица → пропущенные. Лучше: все цитаты → разделы → распределение → таблица.

### Б. Адаптация под LLM

4. **Заменить "Ctrl+C/Ctrl+V/Ctrl+F" на реалистичные инструкции:**
   - Вместо "скопируй точь-в-точь" → "Выведи цитату в блоке `>`, включая все ошибки оригинала. После цитаты укажи первые и последние 5 слов для верификации."
   - Вместо "Ctrl+F стоп-тест" → сделать шаг 2 более тщательным, чтобы к шагу 3 уже было ясно, что покрыто героем. Стоп-тест как "перед каждым предложением" — заменить на проверку по завершении каждого раздела.

5. **Сократить чек-лист** с 40+ пунктов до 10-15 критических. Остальное — в стайлгайд.

6. **Добавить явный промежуточный вывод после шага 2** — список тем с пометками "покрыто героем" / "не покрыто" / "частично". Это заставит модель зафиксировать решение до генерации текста автора.

### В. Борьба с конкретными ошибками

7. **"Выдумывает факты"** → добавить правило: "Каждая цифра в тексте автора должна иметь источник — статья или расшифровка. Если источника нет — удали цифру."

8. **"Сложные формулировки"** → добавить явное правило: "Текст автора будут читать вслух. Максимум 15 слов в предложении. Проверь: можно ли это произнести на одном дыхании?"

9. **"Вкладывает реплики героя в слова Славы"** → усилить правило, превратив его в формат классификации: "Для каждого предложения автора определи: это (а) рыночный/индустриальный факт, (б) переход/связка, (в) вопрос. Если не (а), (б) или (в) — это ошибка, удали."
