# Системный фикс merged-word артефакта Whisper

**Дата:** 2026-05-09
**Цель:** Автоматически детектировать и обходить случаи, когда Whisper схлопнул несколько дублей произнесения в один word-token с увеличенной длительностью, и клип на границе попадает в этот «мусорный» участок.

## Контекст

При прогоне E2E на проекте `2026-04-kogtetochki` обнаружено: row 3 «На моём канале уже было видео про производство когтеточек.» начинался с дубля. В транскрипте на 38.99-40.58 стоит одно «слово» «На» длиной 1.59с. Внутри — два произнесения фразы (партиал + чистовой), но Whisper не разделил их на отдельные токены.

Существующий пайплайн опирается на word boundaries из транскрипта. Word-boundary constraint в snap (добавленный 2026-05-09) не помогает: snap корректно ставит `start = 38.99` (start of word «На»), но это включает внутреннюю мусорную часть.

Ручной фикс — изменить `start = 40.50` — работает, но не масштабируется.

## Подход

Snap-level детект и внутренний silencedetect:

1. **Детект подозрительных слов на границах клипа.** Подозрительное = `word.duration > 1.0s` (типичное слово 0.2-0.5с).
2. **Узконаправленный silencedetect** в пределах слова с низким порогом (`d=0.05`, `noise=-30dB`).
3. **Снап к внутренней паузе:**
   - `start` → к концу последней детектированной паузы внутри первого слова (значит, дубль был до паузы).
   - `end` → к началу первой детектированной паузы внутри последнего слова (значит, мусор после паузы).
4. **Fallback:** если внутренних пауз нет — слово реально длинное, не трогаем.

Запускается только при обнаружении подозрительного слова — не для каждого клипа.

## Изменения

`_scripts/match_timecodes.py`:

- Новая функция `detect_silences_in_range(video_path, t_start, t_end, d=0.05, noise="-30dB") -> list[dict]` — silencedetect через ffmpeg `-ss <t_start> -t <duration>` для узкого окна.
- Новая функция `find_internal_break(file_path, word_at_start, word_at_end, current_start, current_end) -> tuple[float, float]` — возвращает уточнённые `(start, end)` или те же что вошли.
- В `cmd_snap`: перед существующим `snap_to_silence` вызываем `find_internal_break`, обновляем `p["start"]`/`p["end"]`. Word boundary constraints `min_start`/`max_end` для последующего snap пересчитываются от новых значений.

## Тестирование

**Unit:**
- `find_internal_break` с синтетическим словом длиной 2с с паузой внутри → возвращает скорректированные границы.
- Слово 2с без пауз внутри → возвращает оригинальные границы (fallback).
- Слово < 1.0с → без изменений (не подозрительное, никакого silencedetect не запускается).

**E2E:**
- Повторный прогон snap на kogtetochki с откатом ручного фикса row 3. Ожидается: `start` сместится на ~40.50 автоматически.

## Edge cases

- **Клип из одного слова, оно подозрительное.** Обе границы (start первого, end последнего) проверяются независимо.
- **Несколько внутренних пауз в подозрительном слове.** Для `start` — последняя пауза (дубль до неё). Для `end` — первая пауза (мусор после).
- **Подозрительное слово на одной границе, но не на другой.** Проверяется только подозрительная.
- **Очень длинное слово (>3с) без внутренних пауз.** Fallback — не трогаем. Whisper иногда так размечает протяжные слова.

## Что не входит

- Дубли В СЕРЕДИНЕ клипа (не на границах) — это требует разделения клипа на multipart, отдельная фича.
- Пост-процессинг transcript.json для всех слов сразу (вариант B из брейнсторма) — отказались, чтоб не перезапускать search/verify на старых проектах.

## Откат ручного фикса

После реализации откатить ручной патч row 3 в `verified.json` (start вернуть на 38.99) и убедиться что snap всё равно даёт 40.50.
