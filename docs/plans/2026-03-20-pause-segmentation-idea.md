# Сегментация по паузам — идея для дизайна

## Проблема

Текущий подход match-timecodes использует WhisperX word-level таймкоды как точки разреза, а потом snap to silence корректирует их. Это создаёт каскад проблем:

- **WhisperX погрешность ±0.3с** на каждой границе слова
- **Раздутые end-таймкоды**: последнее слово перед паузой получает end = start следующего слова (растягивается на всю паузу)
- **Snap к неправильной паузе**: если WhisperX ошибся на 2с, snap привязывается к соседней паузе вместо правильной
- **Буфер/дефляция как костыли**: каждый патч создаёт побочные эффекты (перехлёсты клипов, лишние секунды в начале)

Конкретные баги в текущей версии:
1. Слова режутся на полуслове ("позже" → "поз", "программе" → "програ")
2. Конец отрезка на 10с позже реального (раздутый WhisperX end)
3. При попытке фикса буфером — соседние клипы перехлёстываются, слова повторяются

## Идея: перевернуть логику

Вместо: "вот точка разреза из WhisperX → подвинь к ближайшей паузе"

Делаем: "вот все паузы → скажи, какая реплика между какими паузами"

### Алгоритм

1. **Находим ВСЕ паузы** в аудио через ffmpeg silencedetect
2. **Паузы делят аудио на сегменты речи** — непрерывные блоки звука между паузами. Каждый сегмент: `{start: silence_end, end: next_silence_start}`
3. **WhisperX используем только для грубой привязки** — определяем, какой сегмент речи соответствует какой реплике сценария. Для этого точность ±2с достаточна — не нужны точные границы слов
4. **Режем по границам пауз** — начало клипа = конец паузы (silence_end), конец клипа = начало паузы (silence_start)

### Почему это лучше

- Слова гарантированно не порезаны (режем в тишине, а не по WhisperX-границам)
- Перехлёстов нет (каждый сегмент речи — атомарная единица)
- Не нужна дефляция, буфер и прочие костыли
- WhisperX ошибки не страшны — нам нужна только грубая привязка "эта реплика где-то здесь"

### Открытые вопросы

- Что если реплика длиннее одного сегмента (Слава говорит без паузы через две реплики сценария)?
- Что если в середине реплики есть пауза (Слава делает вдох)?
- Параметры silencedetect (noise threshold, min duration) — подобрать для конкретных файлов
- Как это работает с интервью героя (другое качество аудио, фоновые шумы)?

## Связь с существующим пайплайном

Новый скилл **не заменяет** match-timecodes, а дополняет его:

```
match-timecodes (проход 1+2) → candidates.json / verified.json
                                    ↓
pause-segmentation               → уточнённые границы
                                    ↓
                              обновлённый script.csv
                                    ↓
build_xml.py                  → FCP XML
```

Match-timecodes отвечает за: какая реплика в каком файле, какой дубль выбрать.
Pause-segmentation отвечает за: где именно резать (точные границы).
