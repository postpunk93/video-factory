# Дизайн: YouTube Script v2

## Цель

Новая версия скиллов для создания сценариев YouTube-видео. Заменяет текущий `/youtube-script` после A/B-тестирования на реальных проектах.

Ключевые отличия от v1:
- Драматургия: 13 best practices интегрированы в процесс
- Адаптивность: анализ материала определяет, какие приёмы применять
- Самопроверка: агент-ревьюер с чеклистом, 1-3 итерации правок
- Разделение контекстов: анализ и написание — отдельные скиллы

## Архитектура

### Два скилла

```
/yt-analyze <project_dir>   →  script/analysis.md
/yt-write <project_dir>     →  script/script_draft.csv
```

### Файлы скиллов

```
.claude/commands/
  yt-analyze.md              — скилл анализа
  yt-write.md                — скилл написания (оркестратор)
  yt-examples.md             — примеры формата (цитаты, подводки, мостики)
  yt-review-checklist.md     — чеклист для агента-ревьюера
```

### Справочники (читаются только `/yt-analyze`)

```
docs/youtube-best-practices/
  01-hook-and-promise.md ... 13-pattern-interrupts.md
```

### Поток данных

```
Человек: /yt-analyze projects/tulips
  → читает materials + 13 best practices
  → выдаёт: таблица цифр, угол, цепочка ценности, выбранные практики, структура
  → сохраняет script/analysis.md
  → СТОП, ждёт подтверждения

Человек: смотрит, корректирует, подтверждает

Человек: /yt-write projects/tulips
  → [основной контекст] читает materials + analysis.md + yt-examples.md
  → строит архитектуру посегментно
  → пишет сценарий
  → сохраняет script/script_draft.csv
  → [агент-ревьюер] читает script_draft.csv + analysis.md + yt-review-checklist.md
  → проверяет, исправляет если нужно (1-3 цикла)
  → обновляет script_draft.csv
```

## /yt-analyze — детали

**Вход:** `<project_dir>/raw/article.md` + `<project_dir>/transcripts/*.transcript.txt`

**Шаги:**

1. **Читает материалы** — статья + все расшифровки
2. **Таблица цифр** — все числа из материалов с источниками
   - Есть в материалах → использовать
   - Можно рассчитать → пометить [РАСЧЁТ] с формулой
   - Нет данных → пометить [НУЖНО УТОЧНИТЬ]
   - НЕ округлять без обоснования, НЕ путать опт и розницу
3. **Денежный вопрос** — трансформирует тему в «почему X стоит/зарабатывает столько»
4. **Цепочка создания ценности** — от сырья до потребителя, 4-7 участников, место героя
5. **Выбор практик** — читает 13 best practice файлов и решает:

   Всегда применяет:
   - 01 hook+promise
   - 02 open loops (3-5 вопросов)
   - 03 re-hooks/pacing
   - 05 interview format
   - 10 presenting numbers
   - 11 CTA/closing
   - 12 visual layer
   - 13 pattern interrupts

   Выбирает по фактуре (0-2 из четырёх):
   - 04 staircasing — если есть нарастающий конфликт в материале
   - 06 misconception-first — если есть распространённое заблуждение
   - 07 curiosity gap — если есть сильный разрыв между ожиданием и реальностью
   - 08 in medias res — если есть яркий момент для старта

   Для каждой выбранной практики — краткое обоснование.

6. **Трёхактная структура** — какие темы в каком порядке, где открываются/закрываются loops
7. **Ключевые цитаты** — 8-12 сильнейших цитат из расшифровок с разметкой, где в структуре они используются

**Выход:** `script/analysis.md`

**Точка контроля:** показывает результат, ждёт подтверждения.

## /yt-write — детали

### Фаза 1: Архитектура (посегментная карта)

На основе analysis.md строит детальный план — не текст, а карту:

```
Сегмент 1: Hook (0:00-0:30)
  Стратегия: [hook+promise / in medias res / misconception-first]
  Приём: конкретное описание
  Цитата героя: [конкретная цитата из analysis.md, если есть]
  Текст Славы: [тезис — о чём говорит]
  Open loops: [какие вопросы открываем]
  Визуал: [что на экране]

Сегмент 2: ...
```

6-10 сегментов. Каждый — с конкретными приёмами, цитатами, числами.

### Фаза 2: Написание

По архитектуре пишет полный текст. Правила:

**Цитаты:**
- Источник — ТОЛЬКО расшифровки интервью (НЕ статья)
- Copy-paste БЕЗ редактирования (сохранять ошибки, повторы, междометия)
- Приоритет самодостаточным цитатам
- Несамодостаточные — только с ПОЛНОЙ подводкой автора

**Распределение:**
- 70% герой (цитатами), 30% автор (вводные, переходы, расчёты)
- Если информация есть в расшифровке → герой говорит сам

**Доступность:**
- Смысловые мостики между темами
- Каждый термин объяснён ДО использования
- Вопросы автора — в пространство, не к герою лично

**Язык:**
- Числа как произносятся вслух
- После расчётов: «Итого: [вывод]»
- Короткие предложения, активный залог

**Разметка для монтажа:**
- `[B-ROLL: описание]` / `[ГРАФИКА: описание]` — визуальный слой
- `[МУЗЫКА: настроение]` — смена музыки
- `[ПАУЗА]` — перед ключевыми числами
- `[INTERRUPT: тип]` — pattern interrupts

**Выход:** `script/script_draft.csv` (Слава, Таймкоды, Герой, Таймкоды)

### Фаза 3: Агент-ревьюер

Отдельный агент со свежим контекстом. НЕ загружает материалы проекта (кроме точечной проверки цитат).

**Чеклист — 4 блока:**

Фактчекинг:
- Каждая цифра есть в таблице цифр из analysis.md
- Расчёты корректны (пересчитать)
- Нет придуманных цифр
- Цитаты дословные (выборочно — 3-4 самые длинные)

Драматургия:
- Hook в первые 30 сек содержит promise и stakes
- Open loops открыты и закрыты в правильных местах
- Re-hooks каждые 60-90 секунд
- Выбранные практики реально применены
- Закрытие на пике, без «подведём итоги»

Доступность:
- Мостик перед каждым переходом
- Термины объяснены до использования
- Итог после блоков расчётов
- Новая информация введена последовательно

Формат:
- 70/30 герой/автор (посчитать строки)
- Автор не пересказывает героя
- Нет диалоговых паттернов
- Числа написаны как произносятся
- Монтажная разметка присутствует

**Логика:**

```
Прогон 1: проверка по чеклисту
  → Всё чисто? → Готово
  → Есть проблемы? → Исправления → обновляет CSV

Прогон 2: повторная проверка
  → Всё чисто? → Готово
  → Ещё проблемы? → Ещё раунд

Максимум 3 прогона. После третьего — сохраняет как есть
+ нерешённые проблемы в script/review_notes.md
```

## Файл примеров (yt-examples.md)

Переработанный `youtube-script-examples.md`. ~200-250 строк вместо 390.

**Оставляем (без примера модель путается):**
- Самодостаточные vs несамодостаточные цитаты — с примерами
- Подводки к цитатам — шаблоны + пример хорошо/плохо
- Распределение контента — антипаттерн пересказа + правильный вариант
- Смысловые мостики — шаблоны + один пример
- Введение новой информации — один пример

**Убираем (правила достаточно чёткие):**
- Таблица цифр — пример переносим в `/yt-analyze`
- Ошибки с цифрами — формулируем как правила
- Диалоговые паттерны — списка запрещённых фраз достаточно
