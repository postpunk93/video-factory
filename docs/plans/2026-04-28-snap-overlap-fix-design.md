# Фикс перекрывающихся частей после snap-to-silence

**Дата:** 2026-04-28
**Статус:** дизайн, готов к плану

## Задача

После `match_timecodes.py snap` соседние части одной CSV-строки в одном файле могут перекрываться по таймкодам. На таймлайне это даёт повтор куска аудио.

Пример из `projects/2026-03-thermobags`, строка 22:

```
термосумки 1.mp4: 04:37.44 — 04:53.15  ← snap утянул конец вперёд на 1.92с
термосумки 1.mp4: 04:50.47 — 05:01.65  ← snap утянул начало назад на 1.72с
                  ▲▲▲▲▲▲▲▲▲ оверлап 2.68с — «садилась за машину» звучит дважды
```

## Причина

`snap_to_silence(start, end, silences, window=2.0)` обрабатывает каждый парт независимо. Между частями в исходнике может не быть `silence` длиннее `d=0.3`, и snap «прыгает» через соседнюю часть к следующей реальной паузе. Конец парта i и начало парта i+1 заходят на одну и ту же территорию.

В дизайне `2026-04-23-cutting-improvements-design.md` оверлап после snap был зафиксирован как known limitation («warning, оставляем как есть»). Сейчас фиксим.

## Решение

Передавать в `snap_to_silence` ограничения по соседям. Часть i не может уехать концом дальше word-начала части i+1 в том же файле, и начало части i+1 не может уехать раньше word-конца части i.

Word-границы берём из `verified.json` (поля `start`/`end` каждого парта) — оригинальные, до snap.

### Изменения в `snap_to_silence`

```python
def snap_to_silence(start, end, silences, window=2.0,
                    min_start=0.0, max_end=float("inf")):
    """Привязывает start к ближайшему silence_end в [min_start, start+0.1],
    end — к ближайшему silence_start в [end-0.1, max_end]."""
```

- `snapped_start = max(min_start, snapped_start)`
- `snapped_end = min(max_end, snapped_end)`
- Если в ограниченном окне нет подходящей тишины — fallback на оригинальный `start`/`end`.

### Изменения в `cmd_snap`

Перед snap каждой части считаем соседей в той же строке и том же файле:

```
parts = row["chosen_parts"]
for i, p in enumerate(parts):
    fname = p["file"]
    # ближайший предыдущий парт в том же файле
    prev = next((q for q in parts[i-1::-1] if q["file"] == fname), None)
    # ближайший следующий парт в том же файле
    nxt = next((q for q in parts[i+1:] if q["file"] == fname), None)
    min_start = prev["end"] if prev else 0.0
    max_end = nxt["start"] if nxt else float("inf")
    ss, se = snap_to_silence(p["start"], p["end"], silences,
                             min_start=min_start, max_end=max_end)
```

Соседи — только в том же файле. Между файлами в одной строке ограничений нет.

### Что НЕ делаем

- **Не ограничиваем между CSV-строками.** Разные строки = разные клипы на таймлайне; даже если их источники в одном файле перекрываются — на финальной сборке они звучат отдельно.
- **Не меняем merge_adjacent.** Логика «сливать парты с gap < 3с в один» остаётся в search-этапе. Сюда фикс не лезет.
- **Не предупреждаем при overlap-fallback.** Когда в ограниченном окне нет тишины, snap молча оставляет word-границу — это нормальный кейс, не ошибка.

## Edge cases

**Word-границы соседей уже пересекаются** (бага search/verify):
`prev.end > p.start` или `nxt.start < p.end`. Снимаем ограничение для этой пары (treat as no neighbor) и пишем warning. Snap работает как раньше; пользователь чинит верификацию.

**Парт в файле один в строке** (соседей в том же файле нет): `min_start=0.0`, `max_end=∞` — поведение идентично текущему.

**Парты в разных файлах** в строке (разнобой между источниками): соседями не считаются, ограничений нет.

## Тестирование

1. **Регрессия на термосумках.** `python _scripts/match_timecodes.py snap projects/2026-03-thermobags`. Проверить отсутствие оверлапов на строках 22, 28, 51, 80, 81, 82, 90.
2. **Регрессия на других проектах с `||`.** Прогнать на `projects/tulips`, `projects/2026-04-kozha`, `projects/2026-04-ustritsy`, `projects/2026-03-vendingi` (если в их CSV есть составные цитаты), убедиться что одиночные парты не сломались.
3. **Юнит-логика:** ручной прогон на синтетических данных не нужен — фикс маленький, проверяется на реальных проектах.
