# Скилл match-timecodes — дизайн

## Задача

Сопоставить реплики из сценария (script.csv) с таймкодами в записях (начитка + интервью). Многопроходный подход: алгоритм → агентная верификация → привязка к паузам.

## Входные данные

- `script/script.csv` — сценарий, 4 колонки: Слава, Таймкоды, Герой, Таймкоды
- `transcripts/*.transcript.json` — word-level транскрипты (от transcribe.py)
- Исходные видео в `raw/` — для silencedetect

## Выходные данные

- Обновлённый `script.csv` с таймкодами в формате `filename.ext, MM:SS.ss -> MM:SS.ss` для обоих спикеров

## Архитектура — три прохода

```
Проход 1 (Python-скрипт)
  script.csv + все transcript.json
  → candidates.json

Проход 2 (параллельные агенты)
  candidates.json + транскрипты
  → verified.json

Проход 3 (Python-скрипт)
  verified.json + silencedetect
  → обновлённый script.csv
```

Промежуточные файлы сохраняются — можно перезапустить любой проход отдельно.

## Проход 1 — алгоритмический поиск

Скрипт `_scripts/match_timecodes.py` (универсальный, принимает пути).

Логика:
1. Загружает все transcript.json, строит для каждого нормализованный текст + карту char→word_idx
2. Для каждой реплики в CSV (колонка 0 — Слава, колонка 2 — Герой):
   - Генерирует n-граммы (от 6 до 3 слов)
   - Ищет во всех транскриптах
   - Собирает все кандидаты: файл, start/end time, word indices, ngram_len
   - Дубли (совпадения ближе 5с в одном файле) схлопывает, оставляя с самой длинной n-граммой

Выход — `candidates.json`:
```json
{
  "rows": [
    {
      "row_idx": 1,
      "speaker": "slava",
      "text": "В первую неделю марта...",
      "candidates": [
        {"file": "1773574086.543356.mov", "start": 24.76, "end": 32.52, "words_start": 40, "words_end": 58, "ngram_len": 5}
      ],
      "status": "single"
    }
  ]
}
```

Статусы: `single` (один кандидат), `multiple` (несколько — дубли/фальстарты), `not_found`.

## Проход 2 — агентная верификация

Параллельные Explore-агенты (~4 штуки, по ~20 реплик).

Каждый агент получает:
- Свой кусок candidates.json
- Контекст ±30 слов вокруг каждого кандидата
- Для `not_found` — полный транскрипт спикера

Задачи по приоритету:

1. **`not_found`** — найти реплику по смыслу (текст мог быть переписан в сценарии)
2. **`multiple`** — выбрать последний полный дубль, отсеять фальстарты. Для героя — подтвердить выбор файла
3. **`single`** — быстрая проверка: начало/конец не обрезают слова

Выход — `verified.json`: по одному выбранному кандидату на реплику + поле `confidence: "high" | "low"`.

## Проход 3 — snap to silence

1. ffmpeg silencedetect (noise=-30dB, d=0.3s) на каждом исходном видео
2. Парсит паузы в массив [{start, end, file}]
3. Для каждой реплики:
   - Начало: ищет ближайший silence_end до текущего start (окно -2с). Ставит start = silence_end
   - Конец: ищет ближайший silence_start после текущего end (окно +2с). Ставит end = silence_start
   - Если паузы нет — оставляет как есть
4. Записывает в script.csv

## Файловая структура

```
_scripts/
  match_timecodes.py              ← универсальный скрипт (проходы 1 и 3)

projects/{name}/
  script/
    script.csv                    ← обновлён с таймкодами
    candidates.json               ← промежуточный (проход 1)
    verified.json                 ← промежуточный (проход 2)
  transcripts/
    *.transcript.json             ← уже были
    *.words_compact.txt           ← генерируется для агентов
```

## Формат таймкодов в CSV

`filename.ext, MM:SS.ss -> MM:SS.ss` — для обоих спикеров. Единый формат упрощает последующую сборку XML.

## Особенности

- Нормализация текста: lowercase, ё→е, убрать пунктуацию
- WhisperX: числа иногда получают таймкоды 0/0 — использовать соседние слова
- WhisperX: end последнего слова перед паузой раздувается — корректируется snap to silence
- При нескольких транскриптах (герой) — поиск во всех, выбор лучшего
- Реплики героя ищутся только в транскриптах из raw/interviews/, Славы — из raw/voiceover/
