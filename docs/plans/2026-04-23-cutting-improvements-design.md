# Улучшение нарезки видео: составные цитаты + очистка интервью

**Дата:** 2026-04-23
**Статус:** дизайн, готов к плану

## Задача

Два независимых улучшения существующего пайплайна:

1. **Составные цитаты героя.** Сценарий (в т.ч. присланный извне в виде CSV) может содержать реплику героя, склеенную автором из нескольких фрагментов — одного или разных интервью. Пайплайн должен определять составные цитаты, находить таймкоды каждого фрагмента и собирать их в таймлайне впритык.
2. **Очистка интервью от оговорок.** Интервью героя прогоняются через `cut_pauses.py` (как сейчас Слава). Вырезаются только гарантированные оговорки: междометия, повторы слов подряд, заикания. Слова-паразиты (`ну`, `типа`, `короче`) в речи героя сохраняются.

## Вход

- Готовый CSV (`script/script.csv`, 4 колонки: Слава / Таймкоды / Герой / Таймкоды). В ячейке «Герой» может быть склейка из нескольких фраз без маркировки границ.
- Автор склеивает **почти дословно**: оригинальные слова сохраняются, возможны мелкие правки (падежи, убранные паразиты).

## Архитектура

Две возможности встраиваются в существующий пайплайн без перестройки. Изменения независимы — можно делать по очереди.

```
raw/interviews/*.{mp4,mov}
      │
      ▼  [A] cut_pauses.py --profile hero
cuts/interviews/*_clean.mp4
      │
      ▼  transcribe.py
transcripts/*_clean.transcript.json
      │
      ▼  script/script.csv (составные цитаты в ячейках)
      │
      ▼  [B] match_timecodes.py search
         1. fuzzy whole-match всей цитаты
         2. если score < 0.85 → split by sentences → поиск каждого
         3. merge adjacent (один файл, gap < 3 сек)
candidates.json (поле parts[])
      │
      ▼  /match-timecodes (агентная верификация, знает про parts[])
verified.json
      │
      ▼  match_timecodes.py snap
script.csv: "file1: tc1 — tc2 || file2: tc3 — tc4"
      │
      ▼  build_xml.py (парсит ||, рендерит N клипов подряд)
assembly/*.xml
```

## Компоненты

### A. `cut_pauses.py` — новые паттерны и профили

Добавляются:

- **Междометия:** `э`, `эээ`, `ммм`, `мм`, `эм`, `ам`, `ох`, `эх`, `хм` — режутся, только если стоят отдельным токеном.
- **Повторы подряд:** одно и то же слово идёт 2+ раз в пределах 1.5 сек → оставляем последний, предыдущие режем.
- **Заикания с дефисом:** регекс `^([а-яё])-\1{1,2}` (например `я-я`, `к-к-как`) → режем фрагмент, оставляем полное слово следом.

**Профили:**

- `--profile slava` (дефолт, текущее поведение): `FILLER_WORDS` + междометия + повторы + заикания.
- `--profile hero`: **только** междометия + повторы + заикания. `FILLER_WORDS` не трогаем — в живой речи `ну`/`типа`/`короче` это стилистика, не паразиты.

Whisper-галлюцинации (`Продолжение следует`, `Subscribe to our channel` и т.п.) **не обрабатываются в cut_pauses**. Правильное место — на шаге транскрибации, через initial_prompt или VAD. Вынесено в Future work.

### B. `match_timecodes.py search` — составные цитаты

Новый шаг в `cmd_search`: вместо плоского списка кандидатов каждая строка получает `parts[]`.

Алгоритм `find_quote_parts(phrase, filtered)`:

1. **Whole-match.** Smith-Waterman по словам (матрица совпадений с допуском на пропуск/замену). Если доля найденных слов подряд ≥ **0.85**, возвращаем один part.
2. **Split by sentences.** Делим цитату по `[.!?]` на предложения. Для каждого — текущий n-грамм поиск (`find_candidates`).
3. **Merge adjacent.** Если два соседних предложения нашлись в одном файле и `start[i+1] − end[i] < 3 сек` — склеиваем в один part.
4. **Unmatched.** Предложение не нашлось → статус `partial`, оно идёт в `unmatched[]` для агента-ревьюера.

Формат `candidates.json`:

```json
{
  "row_idx": 12,
  "speaker": "hero",
  "text": "...",
  "parts": [
    {"candidates": [{"file": "...", "start": ..., "end": ...}], "text": "S1"},
    {"candidates": [...], "text": "S2"}
  ],
  "unmatched": ["S3"],
  "status": "single|multiple|partial|multi_part|not_found"
}
```

Для одиночной цитаты `parts` содержит 1 элемент — обратная совместимость.

### C. Скилл `/match-timecodes` — верификация по частям

Агент видит `parts[]` и верифицирует каждую часть независимо. Финальный `verified.json` содержит `chosen_parts[]` вместо одного `chosen`.

### D. `match_timecodes.py snap`

Итерация по `parts`, snap каждого диапазона к тишине в своём файле. В CSV пишется:

```
file1_clean.mp4: 12:34.10 — 12:39.50 || file2_clean.mp4: 08:17.00 — 08:22.30
```

Разделитель `||` с пробелами. Одиночная цитата — без разделителя (совместимо с текущим `build_xml`).

### E. `build_xml.py` — рендеринг составных цитат

`parse_unified_tc` возвращает `list[part]` вместо одной тройки. В главном цикле для строки с несколькими частями клипы ставятся **впритык** на дорожке героя (V2). Длительность строки = сумма длительностей частей.

Маркеров склейки на таймлайне нет — монтажёр видит N клипов героя последовательно, склейка визуально незаметна (вариант E1 из обсуждения). Это просто и не требует изменения имён/аннотаций.

## Data flow (пример)

CSV-строка: герой произносит «У нас проблемы… Расходы… Кассовый разрыв…».

1. **Preclean.** `cut_pauses.py raw/interviews --profile hero` → `cuts/interviews/*_clean.mp4`.
2. **Transcribe.** → `transcripts/*_clean.transcript.json`.
3. **Search.** Whole-match → 0.42 (не нашлось целиком). Split by sentences:
   - S1 → `Тюльпаны 2_clean: 42:19.34—42:22.80`
   - S2 → `Тюльпаны 2_clean: 42:28.10—42:32.54`
   - S3 → `Тюльпаны_clean: 79:13.50—79:16.80`

   Merge adjacent: S1+S2 разрыв 5.3 сек > 3 → не сливаем. S2+S3 разные файлы → не сливаем. `parts[] = [S1, S2, S3]`, `status=multi_part`.
4. **Verify.** Агент проверяет каждую часть по `words_compact.txt`.
5. **Snap.** Каждая часть snap-ится к тишине в своём файле. CSV:
   ```
   Тюльпаны 2_clean.mp4: 42:19.34 — 42:22.80 || Тюльпаны 2_clean.mp4: 42:28.10 — 42:32.54 || Тюльпаны_clean.mp4: 79:13.50 — 79:16.80
   ```
6. **Build XML.** На дорожке героя три клипа подряд впритык.

## Обработка ошибок

**cut_pauses hero:**
- Профиль обязателен и не равен `slava` — иначе не смягчаем Славу случайно.
- После чистки `<80%` исходной длительности → warning (возможно, слишком агрессивно или плохая транскрипция).
- Ошибка на одном файле — пропускаем с warning, продолжаем с остальными.

**search:**
- Часть не нашлась → `partial`, `unmatched[]`, агент разбирается.
- Несколько кандидатов для части → `multiple` для неё — агент выбирает.
- Whole-match + split дают разные места → доверяем whole-match при score ≥ 0.85.
- Порядок инвертирован (`start[S2] < end[S1]` в одном файле) → warning, агент решает.

**snap:**
- Нет тишины в ±2 сек → оставляем исходный таймкод, warning.
- Пересечение частей после snap в одном файле → warning, оставляем как есть.

**build_xml:**
- Неразборный формат таймкода → warning, строка пропускается.
- Неизвестный файл в одной из частей → строка пропускается целиком (не часть, иначе «дыра» в цитате).

## Что НЕ делаем (YAGNI)

- Автоматический откат к подрезам (подход B «внутри финальных фрагментов») — если `--profile hero` слишком агрессивен, пользователь правит вручную.
- Восстановление пропавших кусков из не-clean оригинала.
- Семантический поиск (embeddings) — автор пишет почти дословно, n-граммы справляются.
- Тестовый фреймворк — ручная проверка на реальных проектах (см. раздел «Тесты»).
